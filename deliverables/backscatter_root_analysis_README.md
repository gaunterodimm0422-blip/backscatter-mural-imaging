# 双 511 keV 符合标记背散射成像 —— ROOT 分析程序

按《请帮用 cern root 写一个分析程序》的结构实现。`.cpp` 与 `.h` 分开，
所有可调参数集中在 `src/BackscatterAnalysisConfig.h`。

---

## 1. 文件清单

| 文件 | 内容 | 需要 ROOT |
|---|---|---|
| `src/BackscatterAnalysisConfig.h` | **全部可调参数**：几何、分辨率、能量窗、符合窗、MLEM、分支命名 | 否 |
| `src/BackscatterAnalysisConfig.cpp` | 两套分支命名的预设 | 否 |

| `src/EventBuilder.h/.cpp` | 需求文档二-2、二-4、二-5、四-2：合并、判选、判选链条表 | 否 |
| `src/MlemReconstructor.h/.cpp` | 需求文档五：系统矩阵、MLEM、收敛判断 | 否 |

这样在没装 ROOT 的机器上也能编译并跑完整套自检，物理部分的正确性与 ROOT 无关。

## 2. 编译与运行

```bash
source /path/to/root/bin/thisroot.sh     # 先让 root-config 可用
make                                      # 编译主程序
make test                                 # 跑自检，不需要 ROOT
```

```bash

# 同时给参照文件（强烈建议，理由见第 6 节）

```

换一批新数据时，先确认分支命名：

```cpp
backscatter::PrintRootFileStructure("your_file.root");   // 打印每棵树与每个分支
```

## 3. 与需求文档的逐条对应

| 需求文档条目 | 实现位置 |
|---|---|
| 二-1 TTree 逐个读取 hit | `HitReader::ReadHitsFromRootFile` |
| 二-2 按 eventID 与探测器合并；重心法位置、最大沉积 hit 的时间、能量求和 | `EventBuilder::BuildDetectorEvents` |
| 二-3 参数化位置、能量、时间分辨率 | `DetectorResponse`，参数在配置头文件 |
| 二-4 两个探测器各自的能量窗 | `SelectionConfig`，在 `BuildAndSelectCoincidences` 中施加 |
| 二-5 符合事件窗 | 同上 |
| 三-1 空间两点之间的直线 | `MakeLineThroughTwoPoints` / `MakeIncidentRayFromTagging` |
| 三-2 由能量计算康普顿散射角 | `ScatterAngleFromScatteredEnergy` |
| 三-3 空间圆锥面 | `MakeScatterCone` |
| 三-4 直线与圆锥面求交 | `IntersectLineWithCone` |
| 四-1 两个交点取物理的那一个 | 同上，符号判定 + `t > 0` + 路径区间 + 物体内判定 |
| 四-2 （原文留空） | 见第 5 节，已补九条判选 |
| 五 MLEM、参数化迭代次数、收敛判断 | `MlemReconstructor` |

**关于圆锥面**：程序同时给了两种解法。`IntersectLineWithCone` 是需求文档的写法
（建曲面、解二次方程、判伪根）；`SolveScatterVertexClosedForm` 是等价的闭式解
（在三角形 源–顶点–命中点 里用正弦定理，`t = |X−S|·sin(θ−α)/sin θ`），
不必构造曲面、不必判伪根，数值更稳、更快，主程序默认用它。
`make test` 会逐事例对拍两者，**4000 个事例上最大差 0.000000 mm**。

## 4. 输入数据分支：一个必须说明的缺口

需求文档附1 的分支列表是：
`m_eventID` `m_trackID` `m_time` `m_edep` `m_posx/y/z` `m_sourcePosX/Y/Z` `m_volumeID`。

**这份列表里没有能区分"两个 hit 来自同一个光子"还是"来自背靠背两个光子"的字段。**

后果：同一个光子先打在背散射探测器上、散射之后又打到标记探测器，
会被当成一次合法符合，而它的运动学完全错误——因为"标记给出方向"这个前提不成立了。

GATE 里对应的字段是 `photonID` 与 `primaryID`。程序的处理是：
**分支存在就自动启用该条判选，不存在就打印一次警告并跳过**，不会静默放过。
若数据里这两个字段另有名字，改 `BranchNames::photon_id` / `primary_id` 即可。

程序支持两套分支命名，在 `InputConfig::schema` 里切换：

| 预设 | 说明 |
|---|---|
| `kAdvisorSchema` | 需求文档附1 的命名，单棵树，按 `m_volumeID` 区分两个探测器 |
| `kGateSchema` | GATE 默认输出，每个探测器一棵树（`Hits_crystal` 与 `Hits_BSdetector`），**默认** |

默认用 GATE 命名，因为目前手上唯一存在的数据是 GATE 产生的。

## 5. 四-2 补齐的物理约束（共九条）

判选链条按下列顺序施加，程序会打印**每一条之后还剩多少事例、切掉了百分之几**，
方便逐条核对：

1. 两个探测器都有能量沉积
2. 两个 hit 来自不同初级光子（数据缺分支时跳过并警告，见第 4 节）
3. 符合时间窗 `|Δt| ≤ 10 ns`
4. 标记探测器能量窗 `[400, 600] keV`
5. 背散射探测器能量窗 `[175, 260] keV`
6. 背散射探测器有效半径 `[20, 200] mm`
7. 标记探测器有效面积 半宽 `25 mm`
8. 入射极角上限 `45°`
9. 散射顶点可解：`cos θ ∈ [−1, 1]`、`θ > α`、`t > 0`、
   源到顶点距离落在 `[1, 280] mm`、顶点落在被检测物体内
10. 散射角范围 `[90°, 180°]`

（第 9 条里"源到顶点距离的区间"与"顶点必须在物体内"两项，是需求文档四-2 留空处
应当补上的内容。两项的参数都在配置头文件里。）

## 6. 为什么主程序要接受一个"参照文件"

参照跑 = 同样几何、同样材料、**只把被检测目标挪出视野**的一次测量。

- 两者相除时，孔径衰减、探测器不均匀性、源强漂移都**精确抵消**；
- 没有它，MLEM 图上的任何结构都无法与重建伪影区分——**MLEM 本身就会随迭代
  放大噪声、制造伪结构**（第 8 节有一个当场发生的例子）；
- 再进一步：把**两个都没有目标**的场跑同一套流程（零假设），结果必须是平的。
  这一步是判断"看到的东西是不是真的"唯一可靠的办法。

主程序在没有参照文件时会打印提醒，并说明此时结果只可用于探路、不可用于下结论。

## 7. 事件合并方式：一个可以自己验证的开关

需求文档二-2 指定"位置采用重心法"。程序把它做成了
`EventBuildingConfig::tagging_position_mode`，默认就是重心法，另有两个选项：

| 选项 | 说明 |
|---|---|
| `kEnergyWeightedCentroid` | 能量加权重心（需求文档指定，**默认**） |
| `kMaxEnergyDeposit` | 取能量沉积最大的那个 hit 的位置 |
| `kEarliestHit` | 取时间最早的那个 hit 的位置 |

之所以做成开关，是因为标记探测器晶体厚 20 mm，在本项目的 GATE 数据上实测到
**71% 的标记光子在探测器内多点散射**；三种口径的横向分辨实测为：
重心法 4.15 mm、康普顿序列重建 2.53 mm、最大沉积晶体基本无效。
改这一项即可自行复现对比，不必改动其他任何代码。

关于时间：程序按需求文档取"能量沉积最大 hit 的时间"。需要说明的是，
**这个时间可以用来开符合窗，但不能用来判断多点散射的先后顺序**——
定序需要 10~100 ps 的分辨，而现实的符合时间分辨是 200~400 ps，差一到两个量级。

## 8. 自检：跑 `make test` 会看到什么

自检**不需要 ROOT**，任何有 g++ 的机器上都能跑。

### 物理内核自检（`test/test_core`）

- **圆锥面解法与闭式解法逐事例对拍**：4000 个事例，有效性判定完全一致，
  顶点最大差 0.000000 mm。
- **与 Python 参考实现逐事例对拍**：同样 4000 个事例，2088 个有效解全部一致，
  最大差 0.000000 mm。参考实现是本项目已在 GATE 数据上验证过的那一套。
- **能量分辨到角度误差的换算表**（背散射探测器 8% FWHM @511 keV）：

  | 散射角 | 散射后能量 | dE′/dθ | σ(E′) | **σ(θ)** |
  |---|---|---|---|---|
  | 90° | 255.5 keV | 2.23 keV/度 | 12.3 keV | **5.5°** |
  | 110° | 218.2 keV | 1.53 keV/度 | 11.3 keV | **7.4°** |
  | 130° | 193.4 keV | 0.98 keV/度 | 10.7 keV | **10.9°** |
  | 150° | 178.3 keV | 0.54 keV/度 | 10.3 keV | **18.9°** |
  | 165° | 172.3 keV | 0.26 keV/度 | 10.1 keV | **38.4°** |

  **越接近 180°，能量对角度越不敏感，角度误差越大。** 这一条决定了这台设备
  在深度方向的能力上限，与算法实现无关。

### 端到端自检（`test/test_chain`）

造 4000 个**已知散射顶点**的合成事例（每个探测器上各放 3 个 hit，用来检验合并逻辑），
走完整条链。结果：

| 自检项 | 结果 |
|---|---|
| 关掉响应时顶点精确还原真值 | 最大误差 0.000000 mm |
| 判选链条剩余数单调不增 | 通过，并打印整张表 |
| 打开需求文档给定的分辨率后 | **横向误差中位 1.91 mm，深度误差中位 11.38 mm** |
| MLEM 对数似然逐次不降 | 通过 |
| 重建图像 | 见下 |

MLEM 图像的质量分布（真值：两条竖线在 x = −15 与 +5 mm，深度 20~40 mm）：

| 区域 | 图像质量占比 | 均匀分布的预期 | 倍数 |
|---|---|---|---|
| 真值两条线上（各 ±6 mm） | **67.5%** | 20% | **3.4×** |
| 真值深度带 15~45 mm | **26.2%** | 25% | **1.05×** |

**横向定位有效，纵向几乎无效。** 这与上面那张角度误差表是一致的，不是实现的问题。

### 顺带发现的一个 MLEM 伪影，值得记下来

第一次跑端到端自检时，MLEM 图像的峰值跑到了深度 97 mm——远离全部真值。
原因是 MLEM 的乘性更新要除以灵敏度，而在网格边缘灵敏度近于零，
几个事例就会被放大成一个假峰。

修法是把灵敏度低于峰值 5% 的像素直接排除出重建区域
（`MlemConfig::minimum_sensitivity_fraction`）。修完之后峰值回到真值附近。

**这就是第 6 节说的"MLEM 会制造伪结构"的一个当场例子**：
如果没有真值可对，这个假峰会被当成一个"深处的发现"。

## 9. 收敛判断

`MlemConfig` 里有三个参数：

- `log_likelihood_relative_tolerance`：相邻两次迭代的对数似然相对改善阈值
- `image_relative_change_tolerance`：图像相对变化阈值
- `patience`：上述任一条件连续满足多少次才判定收敛

两个条件任一连续满足 `patience` 次即停止，并在输出里注明停止原因。
每次迭代的对数似然、相对改善、图像相对变化都记录在 `MlemResult::history` 里。

## 10. 与需求文档参数不一致之处（需确认）

| 参数 | 需求文档 | 本项目此前使用 | 本程序采用 |
|---|---|---|---|
| 标记探测器能量分辨率 @511 | 15% | 12% | **15%（按需求文档）** |
| 背散射探测器能量窗 | [175, 260] keV | [180, 250] keV | **[175, 260]（按需求文档）** |
| 标记探测器位置分辨率 | (1, 1, 2.5) mm | (1.0, 1.0, 2.5) mm | 一致 |
| 背散射探测器位置分辨率 | (1.5, 1.5, 5) mm | (1.55, 1.55, 5.0) mm | **(1.5, 1.5, 5)（按需求文档）** |
| 背散射探测器能量分辨率 @511 | 8% | 8% | 一致 |
| 符合窗 | 10 ns | 10 ns | 一致 |
| 时间分辨率 | 1 ns | 此前未建模 | **1 ns（按需求文档补上）** |

另：需求文档二-3 的"Detector1 的三维位置分辨率是（1.5mm, 1.5mm，5mm）"处
应为 Detector2，已按上下文理解为背散射探测器。

关于背散射能量窗，有一点供参考（不改，只是记下来）：
180° 背散射对应的能量是 511/3 = **170.3 keV**，而窗的下沿 175 keV 只比它高 4.7 keV；
该能量处 8% 分辨对应的 FWHM 约 **24 keV**，也就是说下沿落在分辨率涂抹之内。
两个窗覆盖的角度范围分别是：[175, 260] keV → θ ∈ [88.0°, 156.9°]；
[180, 250] keV → θ ∈ [92.5°, 147.0°]。上沿 260 keV 高于 90° 对应的 255.5 keV，
会放进一部分前向散射事例。
